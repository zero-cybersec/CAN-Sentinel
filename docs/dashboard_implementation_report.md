# CAN-Sentinel — Dashboard Implementation and Evaluation Report

## 1. Project Overview

CAN-Sentinel is an Automotive ECU Intrusion Detection System designed to monitor Controller Area Network (CAN) traffic and identify potentially suspicious communication patterns.

The dashboard module provides a visual interface to monitor CAN traffic, review detector outputs, compare traffic patterns, and analyze available evaluation results.

The dashboard supports the presentation of Machine Learning (ML), Rate-based, and Hybrid detector results.

This report describes the dashboard architecture, implementation, data integration, evaluation metrics, experimental ML results, testing, and current limitations.

## 2. Dashboard Objectives

The main objectives of the dashboard are:

- Monitor CAN traffic information.
- Display normal and simulated high-rate traffic.
- Present CAN message statistics.
- Display available ML detection results.
- Compare ML, Rate-based, and Hybrid detectors.
- Display confusion matrix values and performance metrics.
- Present experimental ML predictions and anomaly scores.
- Display edge-case validation information.
- Generate an HTML-based dashboard report.
- Provide clear and understandable visualization of detector results.

The dashboard uses available CAN traffic records and detector output files to present the results.

### 4.1 Processing Workflow

2. Traffic records are stored in CSV files.

4. Evaluation results are stored in CSV format.

### 7.2 Confusion Matrix Terms

| Term | Meaning |
|---|---|
| TP — True Positive | Attack traffic correctly identified as an attack |
| FP — False Positive | Normal traffic incorrectly identified as an attack |
| TN — True Negative | Normal traffic correctly identified as normal |
| FN — False Negative | Attack traffic incorrectly identified as normal |

### 7.3 Evaluation Formulas

**Precision**

`Precision = TP / (TP + FP)`

**Recall**

`Recall = TP / (TP + FN)`

**F1-score**

`F1-score = 2 × Precision × Recall / (Precision + Recall)`

**Accuracy**

`Accuracy = (TP + TN) / (TP + TN + FP + FN)`

These metrics describe the available evaluation dataset and should not be treated as verified real-world vehicle performance.

## 8. Experimental ML Prediction Analysis

Experimental ML prediction results were integrated into the existing HTML dashboard.

The dashboard displays:

- NORMAL and ANOMALY prediction counts.
- Traffic source information.
- CAN ID and message count.
- Anomaly scores.
- Average, minimum, and maximum anomaly scores.
- Prediction and reference comparison.
- Sample-wise prediction details.

### 8.1 Experimental Prediction Summary

The available experimental dataset contains 80 samples.

| Traffic Type | Samples | ML Prediction | Reference Prediction |
|---|---:|---|---|
| Normal Traffic | 40 | NORMAL: 39, ANOMALY: 1 | NORMAL: 38, ANOMALY: 2 |
| High-Rate Traffic | 40 | NORMAL: 40 | ANOMALY: 40 |

**Total samples:** 80

**Prediction/reference mismatches:** 41

### 8.2 Observations

1. All 40 high-rate traffic samples were predicted as NORMAL by the experimental ML output.
2. The corresponding reference predictions for these samples were ANOMALY.
3. One normal-traffic sample also differed from its reference prediction.
4. A total of 41 prediction/reference mismatches were observed.

### 8.3 Important Limitation

The reference predictions have not been independently verified as ground-truth labels. Therefore, the mismatch count is a comparison result and must not be treated as a final false-positive or false-negative count.

The experimental predictions were loaded from an existing CSV file. The updated `can_model.joblib` model was not independently integrated or executed as part of this dashboard work.

Further investigation with the ML team is required before drawing conclusions about model performance.
